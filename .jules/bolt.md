## 2024-08-09 - Startup Latency and Leak Prevention in Android Splash Screen
**Learning:** Hardcoded startup delays in splash screens (such as 3000ms using raw Handler) introduce artificial delays and degrade Time-to-Interactive (TTI). Furthermore, calling `new Handler()` without an explicit Looper is deprecated and leaks the host Activity context if the Activity is destroyed (e.g., orientation change or back button) while the Runnable is still queued.
**Action:** Explicitly use `Looper.getMainLooper()` to instantiate Handler instances, cache the Handler and Runnable as Activity fields, clear pending callbacks in `onDestroy()` using `removeCallbacks(...)` to prevent memory leaks, and reduce delays to the minimum functional duration (e.g., 1000ms) to maximize app performance and startup speed.
