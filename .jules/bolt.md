## 2024-08-10 - Splash Delay and Context Memory Leak Optimization
**Learning:** Hardcoded splash delays artificially degrade startup performance (Time to Interactive / TTI) and create a bad user experience. More critically, scheduling a deferred task using an anonymous inner runnable in an Activity holding a context reference without cancellation results in context memory leaks if the user exits/leaves the screen early. The default `Handler()` constructor is also deprecated as it lacks explicit looper binding, posing concurrency risks.
**Action:** Always minimize artificial delays in splash/loading views, explicitly instantiate `Handler` with `Looper.getMainLooper()` for thread safety, and cancel any pending deferred runnables in the Activity's `onDestroy()` callback using `removeCallbacks()`.
